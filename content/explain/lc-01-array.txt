--- explain
**思路**

暴力做法是两层循环枚举所有 `(i, j)`，O(n²)。换个角度：遍历到 `nums[i]` 时，我们要找的是“前面有没有出现过 `target - nums[i]`”。把见过的值和下标存进 map，这个问题就变成一次 O(1) 的查询。

**代码讲解**

1. `seen := make(map[int]int, len(nums))`：key 是数值，value 是它的下标；预估容量避免扩容。
2. `for i, v := range nums`：同时拿到下标和值。
3. `if j, ok := seen[target-v]; ok`：if 带初始化语句 + comma-ok。`ok` 为真说明之前见过配对的数，`j` 就是它的下标，直接返回 `[]int{j, i}`。
4. **先查再存**：`seen[v] = i` 放在查询之后，保证不会把同一个元素用两次（比如 `target = 6`、`v = 3` 时不会找到自己）。

**易错点**

- 先存后查会在 `[3, 2, 4], target = 6` 上错误返回 `[0, 0]`。
- 不能只写 `j := seen[target-v]` 再判断 `j != 0`：下标 0 本身就是合法值，必须用 comma-ok 区分“不存在”。

**复杂度**

时间 O(n)，空间 O(n)。

=== lc-217
--- explain
**思路**

判断“有没有重复”就是判断“当前元素之前是否出现过”，用集合记录见过的元素即可。另一种做法是排序后比较相邻元素，O(n log n) 但不需要额外空间。

**代码讲解**

1. `seen := make(map[int]struct{}, len(nums))`：用 `map[int]struct{}` 当集合，`struct{}` 不占空间，只关心 key 在不在。
2. `if _, ok := seen[v]; ok`：值不需要，用 `_` 丢掉，只看 `ok`。
3. 发现重复立刻 `return true`，不必遍历完整个数组。
4. `seen[v] = struct{}{}`：第一个 `struct{}` 是类型，第二个 `{}` 是它的字面量值。

**易错点**

- `map[int]bool` 写法也完全可以：`if seen[v] { return true }; seen[v] = true`，读起来更直观。
- 如果用排序法，注意 `slices.Sort(nums)` 会修改调用方的切片。

**复杂度**

时间 O(n)，空间 O(n)。

=== lc-283
--- explain
**思路**

快慢双指针：`fast` 扫描每个元素，`slow` 指向“下一个非零元素该放的位置”。每遇到非零元素，就和 `slow` 位置交换，然后 `slow` 前进。这样非零元素按原顺序被挪到前面，零自然被换到后面。

**代码讲解**

1. 注释写明了**循环不变量**：`[0, slow)` 是已经处理好的非零元素。写双指针时先想清楚这个区间的含义，代码就不容易错。
2. `for fast := range nums`：只要下标的 range 写法。
3. `nums[slow], nums[fast] = nums[fast], nums[slow]`：多重赋值交换，不需要临时变量。
4. 当 `slow == fast` 时交换的是自己和自己，结果不变，不需要特判。

**易错点**

- 题目要求**原地**修改，不能新建切片再拷回去（虽然能过测试，但不符合要求）。
- 另一种写法是先把非零元素依次覆盖到前面，最后把 `[slow, n)` 全部填 0，写入次数在零很多时更少。

**复杂度**

时间 O(n)，空间 O(1)。

=== lc-26
--- explain
**思路**

数组已经有序，重复元素一定相邻。用写指针 `k` 表示“去重后的长度”，读指针 `i` 往后扫，遇到和已保留的最后一个元素 `nums[k-1]` 不同的值，就写到 `nums[k]`。

**代码讲解**

1. 先处理空切片：否则 `k := 1` 和 `nums[k-1]` 的逻辑会越界。
2. `k := 1`：第一个元素一定保留。
3. `if nums[i] != nums[k-1]`：和**已保留的最后一个**比较，而不是和 `nums[i-1]` 比较。这里两种写法其实等价，但和 `nums[k-1]` 比较的写法可以直接推广到“最多保留两个重复”（LeetCode 80）：改成 `nums[i] != nums[k-2]`。
4. 返回 `k`，调用方只看前 `k` 个元素。

**易错点**

- 函数返回的是长度，测试会检查 `nums[:k]`，后面的元素是什么无所谓。
- 切片作为参数传入时，修改元素会影响调用方（共享底层数组），这正是题目要求的“原地修改”。

**复杂度**

时间 O(n)，空间 O(1)。

=== lc-88
--- explain
**思路**

从前往后合并需要把 `nums1` 的元素往后挪，很麻烦。`nums1` 的尾部有 `n` 个空位，所以**从后往前**合并：每次取两个数组末尾更大的那个，放到 `nums1` 的最后一个空位，永远不会覆盖还没处理的元素。

**代码讲解**

1. `i, j, w := m-1, n-1, m+n-1`：三个指针分别指向 nums1 有效部分末尾、nums2 末尾、写入位置。一行声明多个变量。
2. `for j >= 0`：只要 nums2 还有元素就继续。nums2 放完后，nums1 剩下的元素本来就在正确位置，不用再动。
3. `if i >= 0 && nums1[i] > nums2[j]`：`&&` 短路求值，`i < 0` 时不会访问 `nums1[i]`，避免越界。
4. 每次写入后 `w--`。

**易错点**

- 循环条件写成 `i >= 0 && j >= 0` 会漏掉 nums2 剩余的元素（比如 `m = 0` 时）。
- 相等时取哪个都可以，这里取 nums2 的。

**复杂度**

时间 O(m + n)，空间 O(1)。

=== lc-121
--- explain
**思路**

在第 i 天卖出的最大利润 = `prices[i]` − 之前最低的价格。所以一次遍历，同时维护“到目前为止的最低价”和“到目前为止的最大利润”。

**代码讲解**

1. `lowest, best := math.MaxInt, 0`：最低价初始化为最大整数，保证第一天的价格一定会更新它；利润初始为 0（不交易）。
2. `lowest = min(lowest, p)`：Go 1.21 的内置 `min`，不需要自己写辅助函数。
3. `best = max(best, p-lowest)`：用当天价格减最低价，更新最大利润。因为先更新了 `lowest`，当天买当天卖的利润是 0，不会出错。

**易错点**

- 不能简单地用“全局最大值 − 全局最小值”：最大值可能出现在最小值之前。
- `math.MaxInt` 需要 `import "math"`；也可以直接用 `prices[0]` 初始化（题目保证非空）。

**复杂度**

时间 O(n)，空间 O(1)。

**延伸**

这是最简单的“动态规划 / 贪心”题：状态只有“最低价”一个变量。买卖多次（122）、含冷冻期（309）、最多 k 次（188）都是在此基础上增加状态。

=== lc-1929
--- explain
**思路**

结果就是把 `nums` 拼接两次。重点是练习 `append` 和切片预分配。

**代码讲解**

1. `make([]int, 0, 2*len(nums))`：长度 0、容量 2n。已知最终大小时预分配容量，后面两次 `append` 都不会触发扩容。
2. `append(ans, nums...)`：`...` 把切片展开成可变参数，一次追加所有元素。
3. `return append(ans, nums...)`：append 返回新切片，可以直接作为返回值。

**易错点**

- 写成 `make([]int, 2*len(nums))` 再 append，结果前面会多出 2n 个 0。定长就用下标赋值（`ans[i] = nums[i]; ans[i+n] = nums[i]`），不定长才用 `make(0, cap)` + append。
- 不能直接 `append(nums, nums...)` 当结果：如果 `nums` 容量足够，会修改调用方切片的底层数组。

**复杂度**

时间 O(n)，空间 O(n)（结果本身）。

=== lc-118
--- explain
**思路**

每一行首尾是 1，中间的数等于上一行相邻两个数之和：`row[j] = prev[j-1] + prev[j]`。按行生成即可。

**代码讲解**

1. `rows := make([][]int, numRows)`：二维切片，外层先分配好行数，每一行还是 nil。
2. `row := make([]int, i+1)`：第 i 行有 i+1 个数，**每一行都要单独 make**。
3. `row[0], row[i] = 1, 1`：多重赋值把首尾设为 1；第 0 行时 `row[0]` 和 `row[i]` 是同一个位置，也没问题。
4. 内层 `for j := 1; j < i; j++` 只填中间部分，第 0、1 行不会进入循环。
5. `rows[i] = row`：把这一行放回结果。

**易错点**

- 只 `make([][]int, numRows)` 而不初始化每一行，直接访问 `rows[i][j]` 会 panic（index out of range）。
- 计算第 i 行时要用 `rows[i-1]`，它已经在上一次迭代中赋值了。

**复杂度**

时间 O(numRows²)，空间 O(numRows²)（结果本身）。

=== lc-704
--- explain
**思路**

经典二分查找：在有序数组的闭区间 `[lo, hi]` 里找，每次和中点比较，丢掉一半。

**代码讲解**

1. `lo, hi := 0, len(nums)-1`：**闭区间**写法，`hi` 是最后一个合法下标。
2. `for lo <= hi`：闭区间里只要还有元素（`lo == hi` 时还有一个）就继续。
3. `mid := lo + (hi-lo)/2`：等价于 `(lo+hi)/2`，但不会因为 `lo + hi` 过大而溢出。Go 的 int 是 64 位，这里很难溢出，但这是好习惯。
4. 无条件 `switch` 当 if-else 链用：等于就返回；中点偏小，答案在右边 `lo = mid + 1`；否则在左边 `hi = mid - 1`。
5. 循环结束还没找到返回 -1。

**易错点**

- 区间写法要前后一致：闭区间配 `lo <= hi` 和 `hi = mid - 1`；左闭右开 `[lo, hi)` 配 `hi = len(nums)`、`lo < hi`、`hi = mid`。混用会死循环或漏元素。
- 写成 `lo = mid` 可能死循环（当 `hi = lo + 1` 时 mid 一直等于 lo）。

**复杂度**

时间 O(log n)，空间 O(1)。

**延伸**

标准库 `slices.BinarySearch(nums, target)` 返回 `(下标, 是否找到)`；`sort.Search(n, f)` 找第一个让 `f` 为真的下标，是“找左边界”的通用工具。

=== lc-977
--- explain
**思路**

数组有序但含负数，平方后最大值一定出现在**两端**（最负的或最正的）。用左右双指针从两端往中间走，每次把较大的平方写到结果的末尾。

**代码讲解**

1. `out := make([]int, n)`：结果长度已知，直接定长分配，用下标写入。
2. `l, r := 0, n-1`：左右指针。
3. `for w := n - 1; w >= 0; w--`：写入位置从后往前，每轮写一个数。
4. `a, b := nums[l]*nums[l], nums[r]*nums[r]`：同时算两端的平方。
5. 较大的写入 `out[w]`，并移动对应的指针。

**易错点**

- 直接平方后排序也能过，但是 O(n log n)；这道题考的是利用“两端最大”的性质做到 O(n)。
- 从前往后写（找最小值）不好做，因为最小的平方在数组中间某处，位置不确定。

**复杂度**

时间 O(n)，空间 O(1)（不算结果）。

=== lc-66
--- explain
**思路**

模拟手算加法：从最低位开始加 1。如果这一位小于 9，加完就结束；如果是 9，变成 0 并向前进位。全部都是 9 时（如 999），结果需要在最前面补一个 1。

**代码讲解**

1. `for i := len(digits) - 1; i >= 0; i--`：倒序遍历，从个位开始。
2. `if digits[i] < 9 { digits[i]++; return digits }`：没有进位，直接返回。这里修改的是传入切片本身。
3. `digits[i] = 0`：当前位是 9，加 1 后变 0，继续处理更高位（循环继续就相当于进位）。
4. 能走出循环说明每一位都是 9 且都变成了 0，`append([]int{1}, digits...)` 在最前面插入 1。

**易错点**

- 不能把数组转成整数再加 1：位数可能有 100 位，远超 int64。
- 在切片头部插入元素，Go 里的写法就是 `append([]int{x}, s...)`（或 `slices.Insert(s, 0, x)`），都会分配新数组。

**复杂度**

时间 O(n)，空间 O(1)（全是 9 时需要 O(n) 的新切片）。

=== lc-136
--- explain
**思路**

异或有三个性质：`a ^ a = 0`、`a ^ 0 = a`、满足交换律和结合律。把所有数异或起来，成对出现的数两两抵消，剩下的就是只出现一次的数。

**代码讲解**

1. `x := 0`：0 是异或的单位元。
2. `x ^= v`：复合赋值，等价于 `x = x ^ v`。在 Go 里二元 `^` 是异或，一元 `^x` 是按位取反。

**易错点**

- 用 map 计数也能做，但空间是 O(n)；题目要求常数空间，考的就是位运算。
- 这个技巧只适用于“其他数都出现**偶数次**”的情况；其他数出现三次（137 题）要按位统计 1 的个数再对 3 取余。

**复杂度**

时间 O(n)，空间 O(1)。

=== lc-169
--- explain
**思路**

摩尔投票法：多数元素出现次数超过一半，让不同的元素两两“抵消”，最后剩下的一定是多数元素。维护一个候选人和计数：计数为 0 时换候选人；遇到相同的数加 1，不同的减 1。

**代码讲解**

1. `candidate, count := 0, 0`：一行声明两个变量。
2. 无条件 `switch`，按顺序判断三种情况：
   - `count == 0`：之前的候选人已经被抵消光了，当前数成为新候选人，计数为 1；
   - `v == candidate`：支持者 +1；
   - `default`：反对者，和一个支持者抵消，计数 −1。
3. 最后的 `candidate` 就是答案（题目保证多数元素存在）。

**易错点**

- `case` 的顺序很重要：必须先判断 `count == 0`。
- 如果题目**不保证**多数元素存在，需要再遍历一遍验证候选人的出现次数。

**复杂度**

时间 O(n)，空间 O(1)。也可以用 map 计数（空间 O(n)）或排序后取中间元素（O(n log n)）。
