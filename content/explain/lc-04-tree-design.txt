=== lc-101
--- explain
**思路**

一棵树对称，等价于它的左子树和右子树**互为镜像**。两棵树 a、b 互为镜像的条件：根的值相同，并且 a 的左子树和 b 的右子树互为镜像、a 的右子树和 b 的左子树互为镜像。

**代码讲解**

1. `isSymmetric`：空树是对称的；否则检查左右子树是否镜像。`||` 短路保证 root 为 nil 时不访问字段。
2. `mirror(a, b)` 的终止条件写得很紧凑：`if a == nil || b == nil { return a == b }`——只要有一个是 nil，那么只有两个都是 nil 时才镜像。
3. `a.Val == b.Val && mirror(a.Left, b.Right) && mirror(a.Right, b.Left)`：注意是“外侧对外侧、内侧对内侧”。`&&` 短路，值不同就不再递归。

**易错点**

- 写成 `mirror(a.Left, b.Left)` 判断的是“两棵树相同”，不是镜像。
- 只比较中序遍历结果是否回文是错的，不同结构的树可能得到相同的序列。

**复杂度**

时间 O(n)，空间 O(h)。

=== lc-94
--- explain
**思路**

中序遍历的顺序是“左 → 根 → 右”。递归写法只有三行；这里用**显式栈**模拟递归：先一路向左把节点压栈，左边走到底后弹出栈顶（访问它），再转向它的右子树。

**代码讲解**

1. `var out []int`、`var stack []*TreeNode`：结果和栈都用 nil 切片起步。
2. 外层循环条件 `cur != nil || len(stack) > 0`：还有节点要往左走，或者栈里还有节点没访问。
3. 内层 `for cur != nil`：一路向左，经过的节点都压栈（它们的左子树还没处理，暂时不能访问）。
4. 弹栈：`cur = stack[len(stack)-1]` 取栈顶，`stack = stack[:len(stack)-1]` 出栈。
5. 访问 `cur.Val`，然后 `cur = cur.Right` 去处理右子树；如果右子树为空，下一轮会直接弹出更上层的节点。

**递归写法**（对照理解）：

```go
var dfs func(*TreeNode)
dfs = func(n *TreeNode) {
	if n == nil {
		return
	}
	dfs(n.Left)
	out = append(out, n.Val)
	dfs(n.Right)
}
```

**易错点**

- 外层条件只写 `len(stack) > 0` 会导致一开始栈为空时直接退出。

**复杂度**

时间 O(n)，空间 O(h)。

=== lc-108
--- explain
**思路**

要得到高度平衡的二叉搜索树，每次取有序数组的**中间元素**作为根，左半部分递归构造左子树，右半部分递归构造右子树。中序遍历这棵树正好得到原数组。

**代码讲解**

1. 空切片返回 nil，是递归的终止条件。
2. `mid := len(nums) / 2`：偶数长度时取中间偏右的元素，两种取法都正确。
3. `return &TreeNode{Val: ..., Left: ..., Right: ...}`：结构体字面量取地址，字段里直接写递归调用。多行字面量每个字段后都要有逗号。
4. `nums[:mid]`、`nums[mid+1:]`：切片表达式**不复制数据**，只是共享底层数组的新视图，所以递归的空间开销很小。

**易错点**

- 右半部分是 `nums[mid+1:]`，写成 `nums[mid:]` 会把根重复放进去并可能无限递归。

**复杂度**

时间 O(n)，空间 O(log n)（递归深度）。

=== lc-543
--- explain
**思路**

直径是任意两个节点之间最长路径的**边数**。这条路径一定会经过某个“最高点”节点 n，长度 = n 的左子树深度 + 右子树深度。所以在求每个节点深度的同时，用 `左深度 + 右深度` 更新全局答案。

**代码讲解**

1. `best := 0`：全局最优，闭包可以直接修改它。
2. `var depth func(*TreeNode) int` 再赋值：递归闭包的固定写法。
3. `l, r := depth(n.Left), depth(n.Right)`：后序遍历，先拿到左右子树的深度。
4. `best = max(best, l+r)`：经过 n 的最长路径。
5. `return 1 + max(l, r)`：返回给父节点的是**单边**最长深度（路径不能分叉）。
6. 最后调用 `depth(root)` 并返回 `best`，depth 的返回值不需要。

**易错点**

- 直接返回 `depth(root.Left) + depth(root.Right)` 是错的：最长路径不一定经过根节点。
- “递归函数返回的值”和“要求的答案”不是同一个东西，这是树形 DP 的典型特征。

**复杂度**

时间 O(n)，空间 O(h)。

=== lc-155
--- explain
**思路**

难点是 `GetMin` 要 O(1)。用一个**辅助栈** `mins` 和主栈同步压入、弹出：`mins[i]` 记录主栈前 i+1 个元素的最小值。这样无论弹出多少次，`mins` 栈顶始终是当前栈的最小值。

**代码讲解**

1. `MinStack` 结构体有两个切片字段，注释写清楚 `mins` 的含义。
2. `Constructor() MinStack { return MinStack{} }`：零值的结构体就是可用的空栈，nil 切片可以直接 append。
3. 方法用**指针接收者** `(s *MinStack)`：需要修改字段（切片长度会变）。如果用值接收者，修改的是副本，栈永远是空的。
4. `Push`：新最小值 = `min(val, 当前最小值)`。空栈时直接压入 val。
5. `Pop`：两个栈同时弹出。
6. `Top` / `GetMin`：取栈顶 `s[len(s)-1]`。

**易错点**

- 只用一个变量记录最小值是不够的：最小值被弹出后，无法知道新的最小值。
- LeetCode 用 `Constructor` 作为构造函数名，这是平台约定；Go 惯用的命名是 `NewMinStack`。

**复杂度**

所有操作 O(1)，空间 O(n)。

=== lc-232
--- explain
**思路**

两个栈：`in` 负责入队，`out` 负责出队。出队时如果 `out` 为空，就把 `in` 里的元素**全部倒进** `out`，顺序正好反过来，`out` 的栈顶就是最早入队的元素。

**代码讲解**

1. `in, out []int`：同类型字段可以写在一行。
2. `Push`：直接压入 `in`。
3. `move()`：未导出的辅助方法（小写开头）。只有 `out` 为空时才搬运，否则 `out` 里的元素顺序会被打乱。搬运就是不停地从 `in` 弹出、压入 `out`。
4. `Pop` / `Peek`：先 `move()`，再操作 `out` 的栈顶。
5. `Empty`：两个栈都空才为空。

**易错点**

- 每次 Pop 都把元素倒过去再倒回来也能工作，但每次操作都是 O(n)。
- 在 `out` 非空时继续搬运会破坏顺序。

**复杂度**

均摊 O(1)：每个元素最多入 `in` 一次、搬运一次、出 `out` 一次。空间 O(n)。

=== lc-703
--- explain
**思路**

维护一个**大小为 k 的小顶堆**，堆里保存当前最大的 k 个数。堆顶是这 k 个数里最小的，也就是整体第 k 大的数。每加入一个数：压入堆，如果超过 k 个就弹出最小的。

**代码讲解**

1. `IntHeap` 实现 `heap.Interface`：`Len`、`Less`、`Swap` 用值接收者（不修改切片长度）；`Push`、`Pop` 必须用**指针接收者**（要修改切片本身）。
2. `Push(x any)`：参数是 `any`，用类型断言 `x.(int)` 取出 int。
3. `Pop() any`：只负责移除并返回**最后一个**元素；把堆顶换到末尾、调整堆的工作由 `container/heap` 包完成。
4. `KthLargest` 保存 `k` 和堆指针 `h *IntHeap`。
5. `Constructor` 里逐个调用 `kl.Add(v)` 初始化，复用同一套逻辑。
6. `Add`：调用的是 `heap.Push(kl.h, val)` / `heap.Pop(kl.h)`，**不是** `kl.h.Push`；返回堆顶 `(*kl.h)[0]`（先解引用指针再取下标）。

**易错点**

- 直接调用 `h.Push(x)` 只是 append，不会维护堆的性质。
- `Less` 写成 `>` 就是大顶堆，这里要的是小顶堆。

**复杂度**

`Add` 为 O(log k)，空间 O(k)。

=== lc-705
--- explain
**思路**

自己实现哈希表的“链地址法”：准备若干个桶（这里 769 个），key 对桶数取余决定放进哪个桶，每个桶是一个切片，冲突的 key 放在同一个切片里。

**代码讲解**

1. `const base = 769`：桶数用质数，取余后分布更均匀。
2. `buckets [base][]int`：**数组**的每个元素是一个切片。数组长度必须是常量，所以 base 用 const。零值时每个桶都是 nil 切片。
3. `b := &s.buckets[key%base]`：取**桶的地址**。如果写 `b := s.buckets[...]`，得到的是切片头的副本，append 之后长度的变化不会写回数组。
4. `*b = append(*b, key)`：通过指针修改桶。
5. `Remove`：找到后用“和最后一个元素交换再截断”的方式 O(1) 删除（顺序无所谓）。`(*b)[i]` 的括号是必须的，先解引用再取下标。
6. `Contains`：遍历桶。`range` 读取不需要指针。

**易错点**

- 忘记取地址，`Add` 看起来执行了但集合里什么都没有。
- 实际开发直接用 `map[int]struct{}`，这道题是为了理解 map 的底层原理。

**复杂度**

平均 O(n / base)，key 分布均匀时近似 O(1)。

=== lc-1114
--- explain
**思路**

三个方法在不同的 goroutine 里以任意顺序被调用，要保证按 first → second → third 执行。用两个 channel 当“信号”：`First` 完成后关闭 `firstDone`，`Second` 先等这个信号；`Second` 完成后关闭 `secondDone`，`Third` 等它。

**代码讲解**

1. `chan struct{}`：只传信号不传数据，空结构体不占内存。
2. `NewFoo` 用 make 创建两个**无缓冲** channel。
3. `close(f.firstDone)`：关闭 channel 是一种**广播**，所有正在或之后从它接收的 goroutine 都会立即返回。比发送一个值更合适：不需要知道有几个等待者，也不会因为没人接收而阻塞。
4. `<-f.firstDone`：阻塞直到 channel 被关闭。

**易错点**

- 用 `f.firstDone <- struct{}{}` 发送也可以，但发送方会阻塞到 `Second` 来接收；只有一个等待者时没问题，多个等待者时只能唤醒一个。
- 每个 channel 只能 close 一次，重复 close 会 panic。

**复杂度**

O(1)。

**延伸**

也可以用 `sync.WaitGroup`（Add(1)、Done、Wait）实现同样的效果。channel 的好处是可以和 `select`、超时组合。

=== lc-1115
--- explain
**思路**

两个 goroutine 轮流执行，像传递“令牌”：只有拿到令牌的一方才能打印，打印完把令牌交给对方。用两个容量为 1 的 channel 表示“轮到 foo”和“轮到 bar”。

**代码讲解**

1. `make(chan struct{}, 1)`：**缓冲为 1**，放入令牌时不需要对方正在等待，不会阻塞。
2. `fb.fooTurn <- struct{}{}`：构造时先把令牌交给 foo，让 foo 先开始。
3. `Foo`：循环 n 次，每次 `<-fb.fooTurn` 等令牌 → 打印 → `fb.barTurn <- struct{}{}` 把令牌交给 bar。
4. `Bar`：对称的逻辑。
5. 任何时刻只有一个令牌在流转，所以两边严格交替。

**易错点**

- 如果用无缓冲 channel，最后一次 `Bar` 发送 `fooTurn` 时，`Foo` 已经结束不会再接收，`Bar` 会永远阻塞（goroutine 泄漏）。缓冲 1 让最后这次发送也能完成。
- 用 `sync.Mutex` 很难实现“交替”，因为解锁后谁抢到锁是不确定的。

**复杂度**

时间 O(n)，空间 O(1)。
