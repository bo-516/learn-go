**思路**

`n & (n-1)` 会把 n 二进制里**最低位的 1 变成 0**：n−1 把最低位的 1 变成 0、它右边的 0 全变成 1，再和 n 按位与，右边这些位都清零了。所以反复执行这个操作，执行了几次就有几个 1。

**代码讲解**

1. `for n != 0`：for 当 while 用，还有 1 就继续。
2. `n &= n - 1`：复合赋值，等价于 `n = n & (n - 1)`。

- 逐位检查 `n & 1` 再 `n >>= 1` 也可以，但循环次数等于位数（32 或 64），而这个写法只循环“1 的个数”次。

2 的幂在二进制里**只有一个 1**（1、10、100、1000……）。用上一题的技巧：`n & (n-1)` 去掉最低位的 1 后如果变成 0，说明原来只有一个 1。

- 忘了 `n > 0` 的判断。
- 也可以写 `n&(-n) == n`：`n & -n` 只保留最低位的 1。

**复杂度**

时间 O(1)，空间 O(1)。

**思路**

到第 n 阶的最后一步要么跨 1 阶（从 n−1 阶来），要么跨 2 阶（从 n−2 阶来），所以 `f(n) = f(n-1) + f(n-2)`，就是斐波那契数列。每次只需要前两个值，用两个变量滚动即可。

**代码讲解**

1. `a, b := 1, 1`：分别是 f(0) 和 f(1)，注释写清楚变量含义。
2. `for i := 2; i <= n; i++`：从第 2 阶算到第 n 阶。
3. `a, b = b, a+b`：**多重赋值先求值右边**，用的是旧的 a、b，所以一行就完成了“前进一步”，不需要临时变量。
4. 返回 b，即 f(n)。n = 1 时不进入循环，直接返回 1。

**易错点**

- 拆成两行 `a = b; b = a + b` 是错的：第二行的 a 已经是新值。
- 直接递归 `f(n-1) + f(n-2)` 会指数级重复计算，n = 45 时就非常慢。

**复杂度**

时间 O(n)，空间 O(1)。

**延伸**

这是动态规划最基础的例子：定义状态、写出转移方程、确定初始值，再用“滚动变量”压缩空间。

**思路**

按定义递归会重复计算大量子问题（f(5) 会算两次 f(3)、三次 f(2)……）。用 map 做**记忆化**：每个 f(n) 算一次就记下来，下次直接取。这道题故意用递归闭包写法来练习 Go 的语法。

**代码讲解**

1. `memo := map[int]int{}`：缓存，n → f(n)。
2. `var f func(int) int` 然后 `f = func(n int) int {...}`：**递归闭包必须先声明再赋值**。如果写成 `f := func...`，函数体里还看不到 `f`，会编译报错 `undefined: f`。
3. `if n < 2 { return n }`：f(0)=0、f(1)=1。
4. `if v, ok := memo[n]; ok`：命中缓存直接返回。
5. `memo[n] = f(n-1) + f(n-2)`：计算并缓存。闭包直接访问外层的 `memo`。

- 内层参数也叫 `n`，会遮蔽外层的 `n`，这里是有意的，但阅读时要注意。
- 实际工程中计算斐波那契直接用循环（见爬楼梯），记忆化的价值在于子问题结构更复杂的场景。

**复杂度**

时间 O(n)，空间 O(n)（缓存 + 递归栈）。

**思路**

遍历链表，把每个节点的 `Next` 指针反过来指向前一个节点。需要三个指针：`prev`（已经反转好的部分的头）、`cur`（当前节点）、`next`（暂存下一个节点，因为改完 `cur.Next` 就找不到它了）。

**代码讲解**

1. `var prev *ListNode`：零值是 nil，正好是反转后尾节点的 Next。
2. `cur := head`。
3. 循环体四步：
   - `next := cur.Next` 先保存后继；
   - `cur.Next = prev` 反转指针；
   - `prev = cur` 已反转部分的头前进；
   - `cur = next` 处理下一个节点。
4. 循环结束时 `cur` 为 nil，`prev` 是新的头节点。

**易错点**

- 先改 `cur.Next` 再保存后继，链表就断了。
- 这四步也可以写成一行多重赋值 `cur.Next, prev, cur = prev, cur, cur.Next`，合法但很难读，推荐分开写。

**复杂度**

时间 O(n)，空间 O(1)。递归写法也是 O(n) 时间，但递归栈要 O(n) 空间。

**思路**

两个指针分别指向两个链表，每次把较小的节点接到结果尾部。用一个**哨兵节点（dummy）**作为结果的假头，就不用特判“结果为空时如何设置头节点”。

- 用 `<=` 可以保持稳定（相等时先取 list1）。

**思路**

快慢指针（Floyd 判圈）：slow 每次走 1 步，fast 每次走 2 步。如果有环，fast 会在环里追上 slow；如果没环，fast 会先走到 nil。

- 先比较再移动的话，一开始 `slow == fast == head` 会直接返回 true。
- 用 `map[*ListNode]bool` 记录访问过的节点也能做，但空间 O(n)。

=== lc-203
--- explain
**思路**

删除节点的难点是“删除头节点”和“删除中间节点”写法不同。这里用**指向指针的指针** `p`：它指向“当前要检查的那个指针变量”（一开始是 `head` 本身，之后是某个节点的 `Next` 字段）。要删除时直接把这个指针改成跳过当前节点，两种情况就统一了。

**代码讲解**

1. `for p := &head; *p != nil; {`：`p` 的类型是 `**ListNode`；循环没有后置语句，因为移动与否取决于是否删除。
2. `(*p).Val == val`：`*p` 是当前节点。括号不能省：`*p.Val` 会被解析成 `*(p.Val)`。
3. 删除：`*p = (*p).Next`，直接修改那个指针变量（可能是 `head`，也可能是前一个节点的 `Next`）。删除后 `p` 不动，继续检查新换上来的节点。
4. 不删：`p = &(*p).Next`，让 p 指向当前节点的 `Next` 字段。
5. 返回 `head`：如果头节点被删了，`*p = ...` 修改的正是局部变量 `head`。

**更常见的写法**（哨兵节点）：

```go
dummy := &ListNode{Next: head}
for cur := dummy; cur.Next != nil; {
	if cur.Next.Val == val {
		cur.Next = cur.Next.Next
	} else {
		cur = cur.Next
	}
}
return dummy.Next
```

**易错点**

- 删除后又移动指针，会漏检连续的待删除节点（如 `[7, 7, 7]`）。

**复杂度**

时间 O(n)，空间 O(1)。

**思路**

递归：一棵树的深度 = 1 + 左右子树深度的较大值；空树深度为 0。

**代码讲解**
