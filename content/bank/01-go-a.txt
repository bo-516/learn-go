=== go-01-1
title: 安全地截取子切片
--- desc
实现 `Window(s, i, j)`，返回 `s[i:j]` 的**独立拷贝**：

- 修改返回值的元素，不能影响 `s`；
- 对返回值 `append`，也不能覆盖 `s` 后面的元素。

起始代码直接返回了 `s[i:j]`，它和 `s` 共享底层数组，所以测试会失败。
--- solution
package main

// Window 返回 s[i:j] 的一份独立拷贝。
func Window(s []int, i, j int) []int {
	// @solution
	out := make([]int, j-i)
	copy(out, s[i:j])
	return out
	// @starter
	// return s[i:j] // TODO: 这样会和 s 共享底层数组
	// @end
}
--- test
package main

import (
	"slices"
	"testing"
)

func TestWindowValues(t *testing.T) {
	s := []int{1, 2, 3, 4, 5}
	got := Window(s, 1, 4)
	if !slices.Equal(got, []int{2, 3, 4}) {
		t.Fatalf("Window(s, 1, 4) = %v，期望 [2 3 4]", got)
	}
}

func TestWindowModifyIndependent(t *testing.T) {
	s := []int{1, 2, 3, 4, 5}
	got := Window(s, 1, 3)
	got[0] = 100
	if s[1] != 2 {
		t.Fatalf("修改返回值影响了原切片：s = %v", s)
	}
}

func TestWindowAppendIndependent(t *testing.T) {
	s := []int{1, 2, 3, 4, 5}
	got := Window(s, 1, 3)
	_ = append(got, 99)
	if s[3] != 4 {
		t.Fatalf("对返回值 append 覆盖了原切片的 s[3]：s = %v", s)
	}
}
--- explain
`make` 一块新内存再 `copy`，返回值就和 `s` 彻底无关了。等价写法是 `slices.Clone(s[i:j])`（Go 1.21+）。

如果只想防止 `append` 覆盖原数据、但允许共享元素，可以用**完整切片表达式** `s[i:j:j]`：它把容量限制为 `j-i`，下一次 `append` 必然分配新数组。

=== go-02-1
title: 实现扩容容量计算
--- desc
按 Go 1.18+ `runtime.nextslicecap` 的规则实现 `NextCap(oldCap, needed)`，返回扩容后的新容量（**不考虑**内存 size class 向上取整）。`needed` 是追加后需要的最小长度，保证 `needed > oldCap`。

规则：

1. 如果 `needed` 大于旧容量的 2 倍，直接返回 `needed`；
2. 否则，旧容量 < 256 时，容量翻倍；
3. 旧容量 ≥ 256 时，循环执行 `newcap += (newcap + 3*256) / 4`，直到 `newcap >= needed`。

| oldCap | needed | 结果 |
| --- | --- | --- |
| 4 | 5 | 8 |
| 5 | 11 | 11 |
| 256 | 257 | 512 |
| 300 | 600 | 900 |
--- solution
package main

func NextCap(oldCap, needed int) int {
	// @solution
	doubleCap := oldCap * 2
	if needed > doubleCap {
		return needed
	}
	const threshold = 256
	if oldCap < threshold {
		return doubleCap
	}
	newCap := oldCap
	for newCap < needed {
		newCap += (newCap + 3*threshold) / 4
	}
	return newCap
	// @starter
	// return needed // TODO
	// @end
}
--- test
package main

import "testing"

func TestNextCap(t *testing.T) {
	cases := []struct{ oldCap, needed, want int }{
		{0, 1, 1},
		{1, 2, 2},
		{4, 5, 8},
		{5, 11, 11},
		{128, 129, 256},
		{256, 257, 512},
		{300, 600, 900},
		{512, 513, 832},
		{1000, 1001, 1442},
		{1024, 3000, 3000},
	}
	for _, c := range cases {
		if got := NextCap(c.oldCap, c.needed); got != c.want {
			t.Errorf("NextCap(%d, %d) = %d，期望 %d", c.oldCap, c.needed, got, c.want)
		}
	}
}
--- explain
从 256 开始，`(newcap + 768) / 4` 让增长系数从 2 倍平滑地降到约 1.25 倍：容量越大，每次多要的比例越小，避免大切片浪费太多内存。

真实的 `growslice` 在算出容量后还会按 size class 向上取整，所以 `append([]int64{}, 1, 2, 3, 4, 5)` 的 cap 是 6 而不是 5。

title: 让调用方看到 append 的结果
--- desc
原题里的 `add(s)` 在函数内 `append`，调用方却看不到新元素。实现两种正确写法，都要完成「追加 4，再把第一个元素改成 100」：

func AddReturn(s []int) []int {

	s[0] = 100
	// @starter
	// // TODO
	// @end
	return s
}

func AddPtr(s *[]int) {
	// @solution
	*s = append(*s, 4)
	(*s)[0] = 100
	// @starter
	// // TODO
	// @end
}
--- test

import (

	"testing"

=== go-04-1
title: 用 RWMutex 保护 map
race: true
--- desc
实现一个并发安全的计数器 `SafeCounter`：

- `Inc(key)`：计数加一；
- `Get(key)`：读取计数。

测试会用 50 个 goroutine 并发调用，并开启 `-race`。起始代码没有加锁，运行时会直接 `fatal error: concurrent map writes` 或被竞态检测器报告。
--- solution
package main

import "sync"

type SafeCounter struct {
	// @solution
	mu sync.RWMutex
	// @starter
	// // TODO: 需要一把锁保护 m
	// @end
	m map[string]int
}

func NewSafeCounter() *SafeCounter {
	return &SafeCounter{m: make(map[string]int)}
}

func (c *SafeCounter) Inc(key string) {
	// @solution
	c.mu.Lock()
	defer c.mu.Unlock()
	// @end
	c.m[key]++
}

func (c *SafeCounter) Get(key string) int {
	// @solution
	c.mu.RLock()
	defer c.mu.RUnlock()
	// @end
	return c.m[key]
}
--- test
package main

import (
	"fmt"
	"sync"
	"testing"
)

func TestSafeCounterConcurrent(t *testing.T) {
	c := NewSafeCounter()
	var wg sync.WaitGroup
	for g := 0; g < 50; g++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			for i := 0; i < 200; i++ {
				c.Inc(fmt.Sprintf("k%d", i%3))
				_ = c.Get("k0")
			}
		}()
	}
	wg.Wait()
	total := c.Get("k0") + c.Get("k1") + c.Get("k2")
	if total != 50*200 {
		t.Fatalf("计数总和 = %d，期望 %d", total, 50*200)
	}
}
--- explain
写用 `Lock`，读用 `RLock`，多个读者可以同时持有读锁。`defer Unlock()` 保证函数中途 return 或 panic 时也能释放锁。

=== go-04-2
title: 分片锁 map
race: true
--- desc
一把大锁在高并发下会成为瓶颈。实现一个 16 个分片的 `ShardedMap`，每个分片有自己的锁：

- `ShardIndex(key)`：用 FNV-1a 32 位哈希（`hash/fnv` 的 `New32a`）对 16 取模，决定 key 落在哪个分片；
- `Set(key, v)` / `Get(key) (int, bool)`：只锁 key 所在的分片；
- `Len()`：所有分片元素数之和。
--- solution
package main

import (
	"hash/fnv"
	"sync"
)

const shardCount = 16

type shard struct {
	mu sync.RWMutex
	m  map[string]int
}

type ShardedMap struct {
	shards [shardCount]*shard
}

func NewShardedMap() *ShardedMap {
	sm := &ShardedMap{}
	for i := range sm.shards {
		sm.shards[i] = &shard{m: make(map[string]int)}
	}
	return sm
}

func ShardIndex(key string) int {
	// @solution
	h := fnv.New32a()
	h.Write([]byte(key))
	return int(h.Sum32() % shardCount)
	// @starter
	// return 0 // TODO
	// @end
}

func (sm *ShardedMap) Set(key string, v int) {
	// @solution
	s := sm.shards[ShardIndex(key)]
	s.mu.Lock()
	s.m[key] = v
	s.mu.Unlock()
	// @starter
	// // TODO
	// @end
}

func (sm *ShardedMap) Get(key string) (int, bool) {
	// @solution
	s := sm.shards[ShardIndex(key)]
	s.mu.RLock()
	defer s.mu.RUnlock()
	v, ok := s.m[key]
	return v, ok
	// @starter
	// return 0, false // TODO
	// @end
}

func (sm *ShardedMap) Len() int {
	// @solution
	n := 0
	for _, s := range sm.shards {
		s.mu.RLock()
		n += len(s.m)
		s.mu.RUnlock()
	}
	return n
	// @starter
	// return 0 // TODO
	// @end
}
--- test
package main

import (
	"fmt"
	"hash/fnv"
	"sync"
	"testing"
)

func TestShardIndex(t *testing.T) {
	for _, k := range []string{"a", "user:1", "order:42", ""} {
		h := fnv.New32a()
		h.Write([]byte(k))
		want := int(h.Sum32() % 16)
		if got := ShardIndex(k); got != want {
			t.Errorf("ShardIndex(%q) = %d，期望 %d", k, got, want)
		}
	}
}

func TestShardedMapConcurrent(t *testing.T) {
	sm := NewShardedMap()
	var wg sync.WaitGroup
	for g := 0; g < 8; g++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			for i := 0; i < 500; i++ {
				k := fmt.Sprintf("g%d-%d", g, i)
				sm.Set(k, i)
				if v, ok := sm.Get(k); !ok || v != i {
					t.Errorf("Get(%q) = %d, %v，期望 %d, true", k, v, ok, i)
					return
				}
			}
		}()
	}
	wg.Wait()
	if n := sm.Len(); n != 8*500 {
		t.Fatalf("Len() = %d，期望 %d", n, 8*500)
	}
	if _, ok := sm.Get("missing"); ok {
		t.Fatal("不存在的 key 应返回 false")
	}
}

=== go-05-1
title: 按顺序遍历 map
--- desc
map 的遍历顺序是随机的。实现两个函数，得到确定的顺序：

- `SortedKeys(m)`：返回按字典序排好的所有 key；
- `RankByValue(m)`：按 value **从大到小**返回 key，value 相同时按 key 字典序。

提示：Go 1.23+ 可以用 `slices.Sorted(maps.Keys(m))`；自定义排序用 `slices.SortFunc` 配合 `cmp.Compare`。
--- solution
package main

import (
	"cmp"
	"maps"
	"slices"
)

func SortedKeys(m map[string]int) []string {
	// @solution
	return slices.Sorted(maps.Keys(m))
	// @starter
	// return nil // TODO
	// @end
}

func RankByValue(m map[string]int) []string {
	// @solution
	keys := SortedKeys(m)
	slices.SortStableFunc(keys, func(a, b string) int {
		return cmp.Compare(m[b], m[a])
	})
	return keys
	// @starter
	// return nil // TODO
	// @end
}
--- test
package main

import (
	"slices"
	"testing"
)

func TestSortedKeys(t *testing.T) {
	m := map[string]int{"pear": 3, "apple": 5, "fig": 3, "kiwi": 1}
	got := SortedKeys(m)
	want := []string{"apple", "fig", "kiwi", "pear"}
	if !slices.Equal(got, want) {
		t.Fatalf("SortedKeys = %v，期望 %v", got, want)
	}
}

func TestRankByValue(t *testing.T) {
	m := map[string]int{"pear": 3, "apple": 5, "fig": 3, "kiwi": 1}
	got := RankByValue(m)
	want := []string{"apple", "fig", "pear", "kiwi"}
	if !slices.Equal(got, want) {
		t.Fatalf("RankByValue = %v，期望 %v", got, want)
	}
}

func TestEmptyMap(t *testing.T) {
	if got := SortedKeys(map[string]int{}); len(got) != 0 {
		t.Fatalf("空 map 应返回空结果，实际 %v", got)
	}
}
--- explain
先按 key 排好，再用**稳定排序**按 value 排，value 相同的元素会保持 key 的字典序。也可以在一个比较函数里写两级比较：`cmp.Or(cmp.Compare(m[b], m[a]), cmp.Compare(a, b))`。

=== go-06-1
title: 零值可用的类型与 new
--- desc
对 nil map 写入会 panic。实现一个**零值可用**的 `Registry`：`var r Registry` 声明后就能直接 `Add`，不需要构造函数。

另外实现 `NewInt(v)`，用 `new` 返回一个指向 `v` 副本的指针，每次调用得到不同的指针。
--- solution
package main

type Registry struct {
	items map[string]int
}

func (r *Registry) Add(name string, v int) {
	// @solution
	if r.items == nil {
		r.items = make(map[string]int)
	}
	// @end
	r.items[name] = v
}

func (r *Registry) Get(name string) (int, bool) {
	v, ok := r.items[name] // 读 nil map 是安全的，返回零值
	return v, ok
}

func NewInt(v int) *int {
	// @solution
	p := new(int)
	*p = v
	return p
	// @starter
	// return nil // TODO
	// @end
}
--- test
package main

import "testing"

func TestRegistryZeroValue(t *testing.T) {
	var r Registry
	if _, ok := r.Get("x"); ok {
		t.Fatal("空 Registry 不应查到数据")
	}
	r.Add("a", 1)
	r.Add("b", 2)
	if v, ok := r.Get("a"); !ok || v != 1 {
		t.Fatalf("Get(a) = %d, %v，期望 1, true", v, ok)
	}
}

func TestNewInt(t *testing.T) {
	p := NewInt(42)
	if p == nil || *p != 42 {
		t.Fatal("NewInt(42) 应返回指向 42 的指针")
	}
	q := NewInt(42)
	if p == q {
		t.Fatal("每次调用应返回不同的指针")

	*p = 1
	if *q != 42 {
		t.Fatal("两个指针不应指向同一块内存")
	}
}
--- explain
标准库里很多类型都是零值可用的：`sync.Mutex`、`bytes.Buffer`、`strings.Builder`。做法就是在第一次使用时惰性初始化内部字段。

`new(T)` 分配一个 T 的零值并返回 `*T`；`make` 只用于 slice、map、channel，返回的是已经初始化好的值本身。

=== go-07-1
title: 零拷贝的 string 与 []byte 转换
--- desc
用 Go 1.20+ 的 `unsafe.String` / `unsafe.StringData` / `unsafe.Slice` / `unsafe.SliceData` 实现零拷贝转换：

- `BytesToString(b)`：返回的字符串必须和 `b` 共享同一块内存；
- `StringToBytes(s)`：返回的切片必须和 `s` 共享同一块内存（调用方绝不能修改它）。

测试通过比较底层指针判断是否发生了拷贝。
--- solution
package main

import "unsafe"

func BytesToString(b []byte) string {
	// @solution
	return unsafe.String(unsafe.SliceData(b), len(b))
	// @starter
	// return string(b) // TODO: 这会分配内存并拷贝
	// @end
}

func StringToBytes(s string) []byte {
	// @solution
	return unsafe.Slice(unsafe.StringData(s), len(s))
	// @starter
	// return []byte(s) // TODO: 这会分配内存并拷贝
	// @end
}
--- test
package main

import (
	"strings"
	"testing"
	"unsafe"
)

func TestBytesToString(t *testing.T) {
	b := []byte("hello")
	s := BytesToString(b)
	if s != "hello" {
		t.Fatalf("BytesToString = %q", s)
	}
	if unsafe.StringData(s) != &b[0] {
		t.Fatal("发生了拷贝：字符串没有共享 b 的内存")
	}
	if BytesToString(nil) != "" {
		t.Fatal("nil 应转换为空字符串")
	}
}

func TestStringToBytes(t *testing.T) {
	s := strings.Repeat("go", 4)
	b := StringToBytes(s)
	if string(b) != s {
		t.Fatalf("StringToBytes = %q", b)
	}
	if &b[0] != unsafe.StringData(s) {
		t.Fatal("发生了拷贝：切片没有共享 s 的内存")
	}
	if len(StringToBytes("")) != 0 {
		t.Fatal("空字符串应得到空切片")
	}
}
--- explain
这类转换只在确认是热点、并且能保证不修改数据时才用。`StringToBytes` 返回的切片如果被修改，可能写到只读内存直接崩溃，或者悄悄改掉别处共享的字符串。

=== go-08-1
title: 用 defer 和命名返回值决定提交或回滚
--- desc
实现 `Transfer(tx, steps)`：依次执行每一步，任何一步出错就停止并返回该错误。

要求用 `defer` 根据**最终的 err** 决定调用 `tx.Commit()` 还是 `tx.Rollback()`，两者只能调用其中一个，并且只调用一次。这正是原题里提到的实战写法。
--- solution
package main

type Tx struct{ Log []string }

func (tx *Tx) Commit()   { tx.Log = append(tx.Log, "commit") }
func (tx *Tx) Rollback() { tx.Log = append(tx.Log, "rollback") }

func Transfer(tx *Tx, steps []func() error) (err error) {
	// @solution
	defer func() {
		if err != nil {
			tx.Rollback()
			return
		}
		tx.Commit()
	}()
	// @starter
	// // TODO: 用 defer 根据 err 决定 Commit 或 Rollback
	// @end
	for _, step := range steps {
		if err := step(); err != nil {
			return err
		}
	}
	return nil
}
--- test
package main

import (
	"errors"
	"slices"
	"testing"
)

func TestTransferCommit(t *testing.T) {
	tx := &Tx{}
	ran := 0
	step := func() error { ran++; return nil }
	if err := Transfer(tx, []func() error{step, step}); err != nil {
		t.Fatalf("不应返回错误：%v", err)
	}
	if ran != 2 || !slices.Equal(tx.Log, []string{"commit"}) {
		t.Fatalf("ran=%d, log=%v，期望 ran=2, log=[commit]", ran, tx.Log)
	}
}

func TestTransferRollback(t *testing.T) {
	tx := &Tx{}
	boom := errors.New("余额不足")
	ran := 0
	steps := []func() error{
		func() error { ran++; return nil },
		func() error { ran++; return boom },
		func() error { ran++; return nil },
	}
	err := Transfer(tx, steps)
	if !errors.Is(err, boom) {
		t.Fatalf("应返回第二步的错误，实际 %v", err)
	}
	if ran != 2 {
		t.Fatalf("出错后不应继续执行，实际执行了 %d 步", ran)
	}
	if !slices.Equal(tx.Log, []string{"rollback"}) {
		t.Fatalf("log = %v，期望 [rollback]", tx.Log)
	}
}
--- explain
`return err` 会先把值赋给命名返回值 `err`，再执行 defer，所以 defer 里读到的就是最终结果。注意循环里的 `err :=` 是新变量，`return err` 依然会赋值给外层的命名返回值。

=== go-08-2
title: defer 的执行顺序
--- desc
实现两个函数：

- `DeferOrder(n)`：在循环里注册 `n` 个 defer，第 i 个 defer 把 `i` 追加到命名返回值 `out`。函数体 `return nil` 之后，`out` 应该是 `[n-1, …, 1, 0]`；
- `DoubleOnReturn(x)`：`return x` 之后，用 defer 把返回值翻倍。

这两个函数分别验证了「后进先出」和「defer 能修改命名返回值」。
--- solution
package main

func DeferOrder(n int) (out []int) {
	// @solution
	for i := range n {
		defer func() { out = append(out, i) }()
	}
	// @starter
	// // TODO
	// @end
	return nil
}

func DoubleOnReturn(x int) (result int) {
	// @solution
	defer func() { result *= 2 }()
	// @starter
	// // TODO
	// @end
	return x
}
--- test
package main

import (
	"slices"
	"testing"
)

func TestDeferOrder(t *testing.T) {
	got := DeferOrder(4)
	if !slices.Equal(got, []int{3, 2, 1, 0}) {
		t.Fatalf("DeferOrder(4) = %v，期望 [3 2 1 0]", got)
	}
	if got := DeferOrder(0); len(got) != 0 {
		t.Fatalf("DeferOrder(0) = %v，期望空", got)
	}
}

func TestDoubleOnReturn(t *testing.T) {
	for _, x := range []int{0, 3, -5} {
		if got := DoubleOnReturn(x); got != 2*x {
			t.Errorf("DoubleOnReturn(%d) = %d，期望 %d", x, got, 2*x)
		}
	}
}
--- explain
`return nil` 先把 `out` 置为 nil，然后 defer 按注册的逆序执行，依次追加 3、2、1、0。Go 1.22 起每次迭代的 `i` 都是新变量，所以每个闭包捕获到的值不同。

=== go-09-1
title: 把 panic 转换成 error
--- desc
实现 `SafeCall(fn)`：执行 `fn`，如果它 panic，就把 panic 转换成错误返回，错误信息形如 `panic: <值>`；没有 panic 时返回 nil。

package main

import "fmt"

func SafeCall(fn func()) (err error) {
	// @solution
	defer func() {

		}
	}()
	// @starter
	// // TODO: 用 defer + recover 捕获 panic
	// @end
	fn()
	return nil

=== go-09-2
title: 自带 recover 的 goroutine
race: true
--- desc
子 goroutine 里没被捕获的 panic 会让整个进程崩溃。实现 `Go(fn, onPanic)`：

1. 在新 goroutine 中执行 `fn`；
2. `fn` panic 时不能崩溃，而是调用 `onPanic(panic 的值)`；
3. 返回一个 channel，`fn` 结束（无论是否 panic）后关闭它。

起始代码缺少 recover，测试一跑整个测试进程就会崩溃。
--- solution
package main

func Go(fn func(), onPanic func(any)) <-chan struct{} {
	done := make(chan struct{})
	go func() {
		defer close(done)
		// @solution
		defer func() {
			if r := recover(); r != nil {
				onPanic(r)
			}
		}()
		// @starter
		// // TODO: 捕获 panic 并交给 onPanic
		// @end
		fn()
	}()
	return done
}
--- test
package main

import (
	"testing"
	"time"
)

func wait(t *testing.T, done <-chan struct{}) {
	t.Helper()
	select {
	case <-done:
	case <-time.After(2 * time.Second):
		t.Fatal("等待 goroutine 结束超时：done channel 没有被关闭")
	}
}

func TestGoNormal(t *testing.T) {
	ran := false
	called := false
	wait(t, Go(func() { ran = true }, func(any) { called = true }))
	if !ran || called {
		t.Fatalf("ran=%v onPanic被调用=%v，期望 true, false", ran, called)
	}
}

func TestGoPanic(t *testing.T) {
	var got any
	wait(t, Go(func() { panic("oops") }, func(v any) { got = v }))
	if got != "oops" {
		t.Fatalf("onPanic 收到 %v，期望 oops", got)
	}
}
--- explain
defer 按后进先出执行：recover 的 defer 后注册、先执行，所以 `onPanic` 一定在 `close(done)` 之前被调用。测试里 `<-done` 之后读取 `got` 没有数据竞争，因为 channel 的关闭 happens-before 接收到零值。

=== go-10-1
title: 修复「nil 不等于 nil」
--- desc
下面的 `Validate` 在年龄合法时，返回的 error 却**不等于 nil**：它把一个值为 nil 的 `*ValidationError` 赋给了 `error` 接口，接口的动态类型不为空。

修复它：年龄在 0~150 之间时必须返回真正的 `nil`；否则返回 `*ValidationError{Field: "age"}`。
--- solution
package main

type ValidationError struct{ Field string }

func (e *ValidationError) Error() string { return e.Field + " is invalid" }

func Validate(age int) error {
	if age < 0 || age > 150 {
		return &ValidationError{Field: "age"}
	}
	return nil
}
--- starter
package main

type ValidationError struct{ Field string }

func (e *ValidationError) Error() string { return e.Field + " is invalid" }

func Validate(age int) error {
	var verr *ValidationError
	if age < 0 || age > 150 {
		verr = &ValidationError{Field: "age"}
	}
	return verr // BUG: 接口值 = (*ValidationError, nil)，不等于 nil
}
--- test
package main

import (
	"errors"
	"testing"
)

func TestValidateOK(t *testing.T) {
	for _, age := range []int{0, 18, 150} {
		if err := Validate(age); err != nil {
			t.Errorf("Validate(%d) 应返回 nil，实际 %#v", age, err)
		}
	}
}

func TestValidateInvalid(t *testing.T) {
	for _, age := range []int{-1, 151} {
		err := Validate(age)
		var verr *ValidationError
		if !errors.As(err, &verr) || verr.Field != "age" {
			t.Errorf("Validate(%d) 应返回 *ValidationError{Field: age}，实际 %v", age, err)
		}
	}
}
--- explain
规则很简单：返回 `error` 的函数，没错误时直接写 `return nil`，不要返回某个具体类型的 nil 指针变量。
